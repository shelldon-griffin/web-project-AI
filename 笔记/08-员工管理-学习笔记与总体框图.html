03

三种多表关系

关系 文中场景 落地方法 记忆重点
一对多 一个部门下有多名员工 在“多”的一方保存关联字段，如 emp.dept_id 多方记录指向一方主键
一对一 用户基本信息与身份信息拆表 关联字段指向另一表主键，并增加 UNIQUE 唯一约束限制关联重复
多对多 学生可以选择多门课程 新建中间表，分别保存学生 ID、课程 ID 一条中间表记录表示一次关联

员工管理案例：三张表、两组一对多

原文综合案例将部门、员工和工作经历拆成三张表。一个部门关联多个员工，一个员工可以填写多段工作经历。

表 作用 主要字段
dept 保存部门 id、name、创建与修改时间
emp 保存员工信息 id、name、gender、salary、entry_date、dept_id 等
emp_expr 保存员工的多段工作经历 id、emp_id、起止日期、公司、职位

从约束可以进一步看出： UNIQUE 保证一个关联值最多出现一次，并不能单独保证每条主表记录都一定有扩展记录。理解一对一时，要区分“最多一条”和“必须存在一条”。这条是对约束含义的补充说明。

04

外键与数据一致性

原文用“删除部门后，员工仍保留旧部门 ID”的场景说明：只有关联字段，不代表数据库会自动维护关联一致性。

方式 谁负责约束 本课需要掌握的内容
物理外键 数据库，通过 FOREIGN KEY 声明 插入、修改、删除时由数据库检查关联约束
逻辑外键 应用的业务逻辑 保存关联 ID，由业务代码检查和处理关联关系

物理外键语法可概括为：

SQL
ALTER TABLE emp
ADD CONSTRAINT fk_dept_id
FOREIGN KEY (dept_id) REFERENCES dept(id);

增加约束前，需要先处理已有的无效关联。原文演示添加外键后，删除仍被员工引用的部门会受到约束阻止；这不代表所有外键都默认执行级联删除。

原文最终的员工管理三表案例采用逻辑外键。复习时应记住两种方式的责任划分，不把本课的选型概括成所有项目都必须遵守的结论。

05

多表查询的选择方法

先给出关联条件

直接写 FROM emp, dept 会生成两表记录的组合。若两表分别有 m、n 行，在没有其他限制时，组合数量为 m × n。具体条数取决于当时的数据，应记住计算方法。

员工与部门的主要关联条件是：

SQL
e.dept_id = d.id

再判断哪些记录必须保留

查询方式 保留规则 放到员工场景中理解
INNER JOIN 仅返回符合连接条件的组合 员工没有匹配部门时不会出现在该查询结果中
LEFT JOIN 保留左表记录，右侧无匹配时补 NULL 以员工为左表，可保留未分配部门的员工
RIGHT JOIN 保留右表记录，左侧无匹配时补 NULL 以部门为右表，可保留没有员工的部门

原文分别介绍隐式内连接（逗号加 WHERE）和显式内连接（JOIN ... ON）。左、右外连接可以通过交换两表的位置改写为等价形式。

这里的“保留全部记录”指连接阶段；如果后面还有 WHERE 条件，仍要满足后续过滤条件。

子查询：当前只读到概念

一条 SQL 中嵌套另一条 SELECT，就是子查询。已取得的正文还说明：子查询可以出现在查询或数据修改语句中，外层最常见的是 SELECT。

06

SQL 速查：从需求选择写法

以下是根据原文场景重新整理的教学示例，增加了表别名和结果列别名；未连接数据库执行。

仅查询能匹配部门的员工

SQL
SELECT e.id, e.name, d.name AS dept_name
FROM emp e
INNER JOIN dept d ON e.dept_id = d.id;

保留全部员工，包括没有匹配部门的员工

SQL
SELECT e.id, e.name, d.name AS dept_name
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.id;

保留全部部门，显示对应的员工

SQL
SELECT d.name AS dept_name, e.name AS emp_name
FROM emp e
RIGHT JOIN dept d ON e.dept_id = d.id;

查询工资高于 8000 的员工，并保留没有匹配部门者

SQL
SELECT e.id, e.name, e.salary, d.name AS dept_name
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.id
WHERE e.salary > 8000;

这里筛选的是员工自身的 salary，因此没有部门匹配的员工仍可在满足薪资条件时保留。如果还要求“男性”，可以增加 AND e.gender = 1；这是组合原文已有条件得到的写法。

07

易混点与自测

易混点 应该怎样理解
保存 dept_id 就等于建立了物理外键？ 不等于；还要看是否声明了 FOREIGN KEY 约束
一对一只加一个关联字段即可？ 还要限制其唯一性，否则同一主表记录可能被多条记录引用
内连接会保留所有员工？ 仅保留符合关联条件的组合；缺少匹配部门者可能被排除
左连接一定最终返回左表所有记录？ 连接会保留左表，后续 WHERE 仍可能筛掉记录
员工名称和部门名称都叫 name 怎么区分？ 用 e.name、d.name 指定来源，并用结果列别名区分输出
表取了别名之后怎样引用字段？ 在同一查询中使用该别名，例如 e.dept_id
员工管理是不是只需要员工表？ 本课综合案例还涉及部门表和工作经历表
自测 1：部门与员工是一对多，关联字段放在哪里？

放在员工表中：emp.dept_id 关联 dept.id，即关联字段放在“多”的一方。

自测 2：要显示全部员工，未分配部门者也要显示，应选什么连接？

以 emp 为左表使用 LEFT JOIN dept。没有部门匹配时，部门侧字段为 NULL。

自测 3：学生与课程多对多，怎样设计表？

增加中间表，保存 student_id 与 course_id，分别关联学生表与课程表。

建议复习顺序：画三类表关系 → 解释外键责任 → 区分三种连接 → 根据保留规则写 SQL → 取得剩余原文后补齐业务流程。
